# 电机异响检测台

生产线末端电机轴承异响的纯前端声学检测。浏览器本地完成录音、频谱分析、轴承特征频率
（BPFO/BPFI/BSF/FTF）匹配、共振解调包络分析与合格基线对比，**无后端、无网络上传**。

## 验收指标与当前状态

| 指标 | 要求 | 当前结果 | 说明 |
|---|---|---|---|
| 单台处理时延 | 录音后出结论 < 1s | **29~32ms** | 5s 录音是采集时间，不计入；测试门限留 3 倍余量按 300ms 卡 |
| 异响检出率 TPR | ≥ 95% | **96%**（合成带标签集） | 算法链路验证值，现场需用真实录音复核 |
| 误报率 FPR | ≤ 2% | **0%**（合成带标签集） | 同上 |
| 故障类型准确率 | — | **95%** | 四类轴承故障分别统计 |

> **重要**：TPR/FPR 是统计指标，取决于麦克风一致性、安装距离、转速稳定性和样本质量，
> 代码不能单方面保证。合成信号验收证明的是"算法在已知故障机理下具备目标区分度"；
> 上线验收必须用老师傅双判的真实录音做校准集（见下文现场校准流程）。

## 信号链

```
麦克风 5s @48k
  → Welch PSD（Hann 窗，50% 重叠，8192 点 FFT，≈5.9Hz 分辨率）
  → 轴承特征频率计算（rpm + 轴承几何 N/D/d/α）
  → 共振解调：Butterworth 4 阶带通(1.5–8kHz) → Hilbert 包络 → 65536 点包络 FFT
  → 三路证据融合：基线 dB 超差 / 基线 z-score / 包络冲击突起度
  → 通道打分 → 整机判决 + 故障类型 + 可解释证据
```

特征频率标准公式（外圈固定）：

- BPFO = N/2·fr·(1 − d/D·cosα)　外圈
- BPFI = N/2·fr·(1 + d/D·cosα)　内圈
- BSF  = D/(2d)·fr·(1 − (d/D·cosα)²)　滚动体（冲击重复频率为 **2×BSF**）
- FTF  = 1/2·fr·(1 − d/D·cosα)　保持架

## 目录结构

```
src/
  dsp/        纯函数 DSP 内核（无 DOM 依赖，可独立单测）
    fft.ts        radix-2 FFT/IFFT
    window.ts     Hann/Hamming 窗与增益
    welch.ts      Welch PSD
    bearing.ts    轴承特征频率
    peaks.ts      峰检测、亚 bin 插值、突起度
    envelope.ts   IIR 带通、Hilbert 包络、包络谱
  core/       判决与基线
    config.ts     全部可调阈值（现场校准只动这里）
    baseline.ts   100 台合格机基线统计与 z-score
    detector.ts   主分析流程
  audio/      浏览器采集与持久化
    recorder.ts     AudioWorklet 录音（含 ScriptProcessor 退化路径）
    baselineStore.ts localStorage / JSON 导入导出
  ui/         Canvas 谱图与界面编排
test/         Vitest 单测 + 合成信号生成器 + 评估测试
scripts/      run-eval.ts 离线评估 CLI
```

## 命令

```bash
npm install
npm test          # 43 个单测/评估/性能测试
npm run eval      # CLI 评估报告（支持 --json、--threshold= 调门限）

```

## 现场校准流程（决定 95%/2% 能否达成的关键）

1. **固定测量条件**：麦克风型号、增益、与电机距离/角度、空载转速公差全部写进作业指导书。
   条件漂移会直接体现为基线 z-score 抬升。
2. **录 100 台老师傅确认合格的电机**，界面上逐台"录入合格机"→"生成基线"，导出 JSON 备份。
3. **录校准集**：建议 ≥ 200 台，其中包含老师傅判废的全部故障机（越多越好，尤其稀缺的
   保持架/滚动体故障），每台保留老师傅标签。
4. 把录音接进 `scripts/run-eval.ts`（替换 `loadCase` 为 WAV 目录 + 标签 CSV），
   用 `--threshold` 扫描门限，在 TPR ≥95% 约束下取 FPR 最小的工作点。
5. 修改 `src/core/config.ts` 的默认值并重新构建；阈值变更要连同评估报告一起留档。
6. 上线后保留所有"不合格"录音与老师傅复核结果，按月滚动评估真实 TPR/FPR，
   偏差超 1 个百分点时重新校准。

## 已知边界与后续方向

- 转速默认手工录入；若线上转速波动 > ±1%，建议接转速表或加轴频自动估计（PSD 低频峰）。
- 共振带 1.5–8kHz 是按通用深沟球轴承给的默认值；实际共振峰要用故障机谱图确认后调整
  （`resonanceBand`），选错带会显著拉低包络证据。
- 当前基线是单型号单转速；换型/换转速需要另建基线（JSON 文件名按型号区分）。
- 合成信号的故障注入是理想化周期冲击；真实信号存在滑移、多故障叠加、结构共振调制，
  这是现场 TPR 可能低于合成值的主要原因，也是必须做真实数据校准的原因。
